# Board: emulated Raspberry Pi Pico (test project)

This is a test project: its board is **rp2040js**, a Raspberry Pi Pico emulated in the user's browser running the official firmware (`"board": "rp2040js"` in `boady.json`). Everything above works the same, but:

- The user's **Emulator tab** shows the Pico with a virtual LED and a virtual button on every header GPIO (GP0–GP22, GP26–GP28) and the on-board LED (GP25, `Pin('LED')` / `board.LED`). The LEDs behave like real LEDs: each is wired pin → resistor → LED → GND (lit while the pin is driven high, by your output or a button) unless the user set it to 3V3 → LED → pin (lit while driven low); a pull resistor alone does not light it. The on-board LED is GP25 → resistor → LED → GND, as on a real Pico: lit only while GP25 is an output set high. Each button, while pressed (or switched on), drives its pin high or low as the user configured (default: low, like a button to GND, so use a pull-up); released, the pull resistor decides. You cannot see the tab or press the buttons yourself: ask the user to press a button or tell you what an LED shows when that is the test, and tell them which pin.
- Nothing else is wired: I2C/SPI/UART devices, sensors, displays and analog inputs do not exist. Test with what the program prints first.
- There is only the REPL port: no data serial port and no CIRCUITPY drive (files always go over the REPL).
- It runs slower than a real Pico; allow longer `timeout_ms`.
- Its files live in the browser and survive a page reload; the user can reset them.
